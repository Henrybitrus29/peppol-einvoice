# Setup

```bash
pip install -r requirements.txt
```

## Convert one invoice and validate it
```bash
python -m einvoice convert samples/simple_invoice.json --out /tmp/invoice.xml
```
This runs both validation layers (see `docs/VALIDATION.md`) and prints any issues to stderr.

## Write invoices to an outbox (no network)
```bash
python -m einvoice send samples/simple_invoice.json --outbox outbox --dead-letter dead-letter
```

## Try it against a real Peppol test network sandbox
`PeppolSandboxSink` has only been tested against a local mock server so far (see
`docs/VALIDATION.md`). To actually try it against the real Peppol test network:

1. **Apply for a free sandbox account.** For example, eConnect's sandbox wizard
   (https://econnect.eu/start/sandbox) — this is an application, not an instant API key; expect to wait for
   approval. Storecove is another provider with a sandbox. Read the provider's own docs for their exact send
   endpoint and auth header shape.
2. Once you have a send URL and credentials:
   ```bash
   python -m einvoice send samples/simple_invoice.json \
     --sandbox-url https://accp-psb.econnect.eu/... \
     --headers '{"Authorization": "Bearer YOUR_TEST_TOKEN"}' \
     --dead-letter dead-letter
   ```
3. Documents sent this way stay on the Peppol **test** network and never reach a real recipient — that's the whole
   point of a sandbox — but double-check your provider's own confirmation of this before sending anything.

## Re-process failures once the cause is fixed
```bash
python -m einvoice replay --sandbox-url ... --headers '...' --dead-letter dead-letter
```

## Run the tests
```bash
python -m unittest discover -s tests -t .
```
85 tests, including 16 that validate real generated invoices against the official EN 16931 Schematron rules,
and a set that runs the CLI as a real subprocess to check its exit codes.

## Validating an invoice from elsewhere (not generated by this project)
`einvoice.validate.validate_xml(xml_string)` runs any UBL invoice or credit note XML string through the same
official rules — useful for checking output from a different system, not just this mapper's own.
